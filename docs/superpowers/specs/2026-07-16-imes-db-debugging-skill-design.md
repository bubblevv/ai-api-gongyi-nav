# IMES 数据库排错 Skill 通用化设计

## 目标

将个人技能 `zydmes-db-debugging` 重命名并改写为 `imes-db-debugging`，用于维护不同客户的 IMES 数据库。技能不得假设固定客户、数据库名、连接环境、服务器、账套或诊断目录前缀。

## 保留范围

- SQL Server 存储过程、业务审核脚本和生产问题的根因排查流程。
- `BDJB`、PDA 保存/取数、报工、领料、批号、事务和结果集契约等通用 IMES 业务模式。
- 先读取对象定义与真实数据、再做最小兼容修改的原则。
- 解析、部署确认、聚焦查询和回滚包裹执行等验证方法。
- 新问题形成稳定规律后，补充通用模式资料的自改进机制。

## 删除范围

- `ZYDMES`、`SGMYMES` 等客户或数据库名称。
- `ZYDMES正式` 等固定连接环境。
- 固定服务器、账号、密码文件和本机专属连接配置路径。
- 具体客户单据、事故日期、`BDJB_ID` 和仅适用于单一客户的业务结论。
- 固定的 `diagnostics/ZYDMES_*` 输出目录规则。

## 运行时上下文解析

技能按以下优先级确定目标环境：

1. 用户明确指定的数据库、客户账套或连接环境。
2. 当前 SQL 文件中的 `USE [database]`、对象限定名和诊断目录上下文。
3. 当前项目的规则文件、配置文件或已配置的数据库工具环境。
4. 信息仍不足时，只执行安全的只读检查，并向用户确认目标环境；不得猜测数据库名或连接。

凭据只能从已有安全配置或环境变量解析，不写入技能、脚本或回复。

## 文件结构

```text
imes-db-debugging/
├── SKILL.md
├── agents/openai.yaml
└── references/
    ├── workflow.md
    └── patterns.md
```

- `SKILL.md`：触发条件、核心原则、标准流程和安全规则。
- `workflow.md`：环境发现、调查、变更和验证方法。
- `patterns.md`：仅保留跨客户可复用的 IMES 业务模式。
- `openai.yaml`：显示名称、简介和默认提示全部改为通用 IMES 表述。

## 迁移方式

直接将目录改名为 `imes-db-debugging`，同步修改 frontmatter、标题、验证命令和 UI 元数据。旧的 `zydmes-db-debugging` 目录不保留，避免两个技能重复触发。

## 验证标准

- 技能目录和 frontmatter 名称均为 `imes-db-debugging`。
- `quick_validate.py` 校验通过。
- 全目录扫描不包含客户专属数据库名、固定连接环境或本机凭据路径。
- 通用 IMES 关键词仍可触发：`BDJB`、PDA、报工、领料、批号、存储过程、SQL Server、事务与结果集错误。
- 使用两个不同数据库名的示例请求时，技能都从上下文识别目标库，不生成写死的 `USE [ZYDMES]` 或固定连接名。

## 非目标

- 不修改当前项目中的 SQL、C++、数据库配置或历史诊断脚本。
- 不连接或改动任何正式数据库。
- 不把客户专属历史案例迁移到通用技能中。
